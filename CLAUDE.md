# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
yarn dev              # dev server at http://localhost:3000
yarn build            # tsc + vite build to /build
yarn lint             # ESLint
yarn format           # Prettier write
yarn format:check     # Prettier check (used in CI)
yarn test             # Vitest watch mode
yarn test:run         # Vitest single run (used in CI)
yarn test:coverage    # Vitest with v8 coverage, outputs coverage/coverage-summary.json
```

**Run a single test file:**
```bash
yarn test src/tests/CommonHooks.test.tsx
```

## Architecture

### Repo layout

The repo has two top-level concerns:

- `src/` (plus `package.json`, `vite.config.ts`, etc. at the repo root) - the React/Vite app (all frontend work happens here)
- `scripts/` - Python scripts called by GitHub Actions to regenerate `src/data/*.json`

### Routing

`src/main.tsx` uses `createHashRouter` (required for GitHub Pages). Four routes:
- `/` - HomeContent
- `/experience` - ExperienceContent
- `/hobbies` - HobbyContent
- `/asher-zone` - AsherZoneContent (Easter egg, floating particle physics)

### Component model

`Home.tsx` is the persistent shell: it owns the MUI drawer, AppBar, theme provider, and keyboard shortcuts. Page components are rendered inside it as route children. All hooks live in `src/hooks/CommonHooks.tsx` - this is the single file for `useAppTheme`, `useLastFm`, `useKeyboardShortcuts`, `usePageTitle`, and `useGitHubRepo`.

### Theme

`useAppTheme()` manages light/dark mode. State persists to `localStorage` under the key `theme`. Default is dark mode. The full MUI theme object (palette, typography, component overrides) is built inside this hook - there is no separate theme file.

### Static data pipeline

Two JSON files in `src/data/` are auto-generated by GitHub Actions and committed to the repo. They are imported directly at build time - there are no runtime fetches for this data.

| File | Generator | Schedule | Consumer |
|---|---|---|---|
| `pulse.json` | `scripts/summarize.py` via `pulse.yml` | Every 3 days | `GitHubPulse.tsx` |
| `stats.json` | `scripts/generate_stats.py` via `stats.yml` | Weekly Mon 02:00 UTC | `SiteStatsWidget.tsx` |

`pulse.json` contains an AI-generated summary of recent commits (Mistral via GitHub Models API). `stats.json` contains Vitest coverage percentages and Lighthouse scores. If these files need regenerating locally, run the Python scripts directly - they have no dependencies beyond the standard library and `requests`.

### Last.fm integration

`useLastFm()` in `CommonHooks.tsx` polls the Last.fm API every 30 seconds. The API key and username (`nightrunner_ks`) are hardcoded in that file - this is intentional, the key is public. The hook fetches the top 3 genre tags per track (tries track tags first, falls back to artist tags). Errors are swallowed silently since this is a non-critical display feature.

### GitHub repo cards

`useGitHubRepo(owner, repo)` fetches live star/fork counts and language from the GitHub API at runtime in the browser. No auth token - uses the public rate limit.

### AsherZone

`src/modules/AsherZone.ts` is a self-contained canvas/physics module (~370 lines). It is intentionally excluded from test coverage. Do not add it to the coverage include list.

### Build output

Vite outputs to `/build` (not `/dist`). The `CNAME` file is written by the deploy workflow, not committed to the repo.

## Code style

Prettier config: single quotes, semi, 2-space indent, 100-char print width, trailing commas. ESLint uses the modern flat config format (`eslint.config.js`). TypeScript strict mode is on with `noUnusedLocals` and `noUnusedParameters`.

## Tests

Test files live in `src/tests/` and mirror component names. `AsherZone.ts` and `AsherZoneContent.tsx` are excluded from coverage. The setup file (`src/tests/setupTests.ts`) only polyfills `scrollIntoView` - keep it minimal.
